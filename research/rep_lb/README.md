# rep_lb: Lean lower-bound generator for one-a-side bipartite mask instances

    python3 gen.py N M MASK K out.lean MODULE [--with-upper] [--no-check]

Writes `out.lean` whose last theorem `PEqualNP.Outside.<MODULE>` is

    ¬ PEqualNP.Represents.RepSizeAtMost (fun (u : Fin N) (v : Fin M) => (MASK : ℕ).testBit (M * u.val + v.val)) K

(`--with-upper`: `RepSizeAtMost A (K+1) ∧ ¬ RepSizeAtMost A K`, the "value" form of the accepted
L_meta_206xx files; refused when no circuit of size K+1 exists).
Exit codes: 0 written, 2 REFUSED (a circuit of size <= K exists; it is printed and re-checked by the Python
mirror, so a refusal is a proof that the statement is false), 3 degenerate instance, 4 own rule check failed.

Files: `gen.py` (CLI, Lean text, CONTRIBUTING text check), `model.py` (exact Python mirror of the Lean
definitions and of the search), `tpl.py` (engine text copied from accepted L_meta_20635).

## Method (what the accepted files do; their generator `notes/tools/improve/gen/mkrep.py` is not in any repo)

Accepted family: L_meta_6343 (engine), L_meta_20588 .. 20636 (5x5, `¬ RepSizeAtMost` at K = exact-1).
Header: "Generated by notes/tools/improve/gen/mkrep.py: graph 5 x 5, mask M, exact size S".

1. Cells with mask bit 1 are `pos`, with bit 0 `neg`, both in row-major order (bit index `m*u+v`).
2. Sample pair number `i`, `0 <= i < P = |pos|*|neg|`, is (pos[i // |neg|], neg[i % |neg|]).
   A wire is a bit vector of width `2P` (type `BitVec (2P)`): bit `i` holds the wire value on the negative
   cell of pair `i`, bit `P+i` its value on the positive cell. Input wire j (left vertex u = j < N, right
   vertex v = j-N) is the unit-vector value on the cell of the sample. `goal` = zeros on the low half, ones on
   the high half. `rawInputs` reproduced bit-for-bit for L_meta_20635 (checked).
3. A circuit that represents the graph computes `goal` on all samples (every cell is a sample). Compiling it
   backwards gives a *live set* chain (`live`, `compress`): a set of at most K+1 wires, each step replaces
   a,b by z = a&b or a|b (optionally keeping a and/or b) until the set is {goal}. A live set must *separate*
   every pair (some wire is 1 on the positive and 0 on the negative sample: `cuts = -1`, lemma `cuts_full`).
4. `optimized K extra l` is the executable search (`dispatch` keeps a/b only while room is left, children
   must keep `cuts = -1`). `optimized_complete`: live set => search true. The file must show that every
   sublist `l` of the N+M inputs with `length <= K+1` and `cuts l = -1` has `optimized K (K+1-length) l = false`.
   Differences from L_meta_20635 (which checks all 2^(N+M) sublists with `optimized` directly):
   * the start set `l = inputs` is not excused by `len_big` but searched too (needed when N+M <= K+1, e.g. 3x5 K=7);
   * the surviving starts (full cuts) are listed by the generator (`starts`, index lists; `frontOK` checks by
     `decide +kernel` that no other sublist has full cuts) and each is proved by a *split frontier*: `kids` / `expand`
     is `dispatch` rewritten as a list (lemma `dispatch_kids`), `fr d F` the d-fold expansion, `fr_sound` turns
     "all states of `fr d F` fail at level K-d" into "F fails at level K". The frontier is cut into chunks of c
     consecutive states, each chunk its own `decide +kernel` theorem. REASON: the kernel keeps its caches until the
     theorem ends, about 0.6 MB and 10 ms per `optimized` call; one 25k-call theorem peaked at 12 GB and was OOM-killed,
     the same search in chunks of ~2000 calls peaks at +1.5 GB over the bare Mathlib import (7 GB RSS, shared pages).
5. `no_small` ties it together; the final theorem applies it to `hC.2.1 : C.size <= K`.
6. A search that *succeeds* is a real circuit (gates are read off the path) so the same code both refuses a
   false statement and, with `--with-upper`, supplies `upperC` for the K+1 half.

`model.l_pairs / l_kids_w / frontier` mirror `pairs`, `kidsW`, `fr` in the exact list order, so chunk
boundaries (`drop (c*j)`, `take c`) agree with Lean.

Python search = `model.Search`: same pair enumeration, same `extra` accounting, memoised on the sorted tuple of
words (Lean's result depends on the multiset only; duplicates are kept, as in Lean).
`unfolded_cost` counts Lean's `optimized` calls (no memo in Lean): printed by gen.py as the kernel work.

## Pitfalls

* A file that declares its own `inductive`/`structure` (the ReplayTree tables of L_meta_6340/10289 style)
  is "not merged by the program" (CONTRIBUTING plain-file rule 5). This generator uses only the brute engine.
* Inputs must be pairwise distinct words (`inputs_nodup` is `decide`d). Degenerate N or M = 1, or an empty or
  complete graph, are refused (exit 3).
* Comments must avoid the banned words even as substrings (`elab` in "elaborate", `attribute`, a `#`, a double
  quote). `gen.py` re-checks the text (`check_rules`).
* `import Mathlib` first, then `import PEqualNP.Defs`, and the word import nowhere else.
* Shell arithmetic overflows past 2^63; all numbers here are produced by Python.
* The cut filter `cuts l != -1` makes many starts free; the cost is in `optimized` for the surviving starts.

## Sizes (this machine, one Lean build at a time)

Kernel cost is about 10 ms and 0.6 MB per `optimized` call (printed by gen.py as "optimized calls", counted
without memo exactly as Lean evaluates). Rule of thumb: <= ~100k calls fits the 20 min kernel limit with chunks;
a few million do not (no memo tables: those need an own data type, which the plain-file rules refuse).
Python search itself is instant for all of the below.
